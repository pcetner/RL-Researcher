# Legacy access and migration

Auto-SM64 is the first acceptance customer. Only the frozen JEPA closed-loop comparison is migrated. Other scientific studies and training adapters remain legacy; they are not silently registered as runnable experiments.

Before removal, both actual working trees, their uncommitted/untracked source, Git revisions/diffs/hook configuration, dependency records, and installed toolkit skills were archived outside the package in the sibling `research-reduction/baseline` directory. ZIP contents were verified against SHA-256 inventories. User modifications in installed skills were preserved. Model checkpoints, datasets, specifications, decisions, approvals, queues, ledgers, trajectories and reports stay at their original paths.

The baseline includes a frozen legacy runtime and a representative report regenerated into `regenerated-report`, separate from original evidence. Legacy source is outside the ordinary import path and absent from the reduced wheel. The dependency record describes its original local interpreter environment. Restoring legacy work requires that environment and its original project data paths; the new application does not install or upgrade legacy dependencies.

Historical reports are exposed through an explicit static index and sandboxed without scripts, forms or navigation. Their original files are not rewritten. The reduced toolkit never reactivates old report controls or held work.

Removed capabilities include research decisions/reviews/approvals/queues, global findings and plan synchronization, scientific registration/run-kind hierarchies, generic verdicts and scientific gates, forecasting, watchers, notifications, remote coordination, generic report/rendering/plotting systems, public command collections, packaged policy skills and toolkit-owned hooks. New active documentation consists only of webpage use, LLM authoring, the API, live evidence/recovery and this migration guide.
