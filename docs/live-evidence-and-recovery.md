# Live evidence and recovery

Execution state flows one way: completed project transition → observational evaluator → coherent sample → supervisor journal → webpage projection. The evaluator must not influence action selection. Each sample carries trial, attempt, phase, decision, capture time, metric definitions/counts, and an optional immutable preview reference.

The supervisor is the journal's sole writer. A worker communicates through an authenticated local process channel and waits for acknowledgment. Publication failures are fatal to required evidence; the execution stops rather than pretending updates are durable. The current state is rebuildable from the manifest and journal. Trial results, checkpoints and artifacts have separate saved files.

Heartbeat and ordinary samples use five-second cadence. Phase changes, reset messages, failures and committed checkpoints publish immediately. The webpage polls using a journal cursor. Older response generations and cursors are discarded. Browser disconnection labels displayed data cached; a missing worker heartbeat for 30 seconds shows Unresponsive. Process launch, heartbeat and measured progress are distinct facts.

Auto-SM64 shows the a looping time-lapse of the last twelve sampled native frames, cumulative 200-unit ground-cell coverage, parking over valid 25-decision windows within radius 100, and running mean predicted-minus-realized novelty. Parking is unavailable before 25 observations. Random novelty is not applicable. Novelty is never compared across checkpoint representation scales. Coverage controls use the same action seed and only the observed decision prefix. Detailed action entropy, repetitions, resets, predicted/realized pairs remain in trial details.

Preview bytes are written completely, hashed, and atomically published before a sample references them. Identical bytes reuse the URL while every sample retains a new capture time. A missing or unencodable image does not invalidate otherwise valid metrics. Full per-decision trajectories and traces are independent of preview sampling. Charts use true decision coordinates; downsampling preserves endpoints and per-bucket extrema.

Checkpoint publication copies payload into staging, flushes it, records identity/progress/hashes, atomically renames it, then commits the event. Keep the latest two committed checkpoints. Partial staging writes cannot replace the previous publication. Resume validates captured runtime/project source, interpreter, dependencies, external inputs and checkpoint hashes. It uses original deadlines and cannot replenish time. It skips completed trials and resumes finalization alone when needed. A started trial without a valid checkpoint requires a new execution; a completed-trial boundary can continue with the next trial.

Each resume creates an attempt. Old uncheckpointed sample history stays in the journal metadata. The resumed plot starts at the recovered checkpoint and identifies the discontinuity instead of merging lost progress. Viewer code is excluded from execution identity, so viewer maintenance does not invalidate recovery.

Execution directories contain manifest.json, source/project, source/toolkit, events.jsonl, state.json, artifacts.json, artifacts, trials, results.json, worker.log and supervisor.log. The worker's working files are not authoritative recovery evidence. The original process is unnecessary for later viewing.

Live preview retention: the viewer plays at eight frames per second, with the bounded set of images preloaded and labels the sampled time span; this is a time-lapse, not real-time video. After an execution stops, the local server deletes older live-preview artifact copies, keeping twelve captures per trial for later playback. A two-minute grace protects recent publications, and paths also referenced by durable artifacts are never deleted. Cleanup does not run during execution. Journal capture metadata, complete trajectories, checkpoints, and final start/middle/end evidence are preserved. Cleanup resumes when the server is reopened.

Study progress shows completed/total trials and a decision-budget progress bar. Approximate time remaining uses median completed-trial wall time, adjusted for the current trial�s progress; it excludes final analysis, appears only during responsive execution, and is unavailable before a trial completes. It is not the hard budget deadline.

The trial selector defaults to AUTO, following the current trial (or the last trial after completion). Pending trials are excluded; manually selecting a started trial pins the view until AUTO is selected again. Measurements are grouped next to the preview. Only plain-language metric explanations appear in the definitions disclosure; recovery metadata lives in Technical details.
